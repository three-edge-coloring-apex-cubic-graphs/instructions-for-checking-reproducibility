# Instructions for checking reproducibility

For any source code that correctly implements the pseudocode in our paper, together with the required algorithms in [IKM+26](https://arxiv.org/abs/2603.24880) to check the lemmas in our paper, the following key metrics should be consistent.
The values produced by our original implementations are shown in the table below.

| Lemma     | Metric/Description                                                                         | Expected Value |
| --------- | ------------------------------------------------------------------------------------------ | -------------- |
| Lemma B.1 | Size of $\mathcal{R}^{*-\mathcal{K}}$                                                      | 747            |
| Lemma B.1 | Maximum amount of charge of the combined rules in $\mathcal{R}^{*-\mathcal{K}}$            | 5              |
| Lemma B.2 | Number of cartwheels whose center degree $7$ enumerated by `enumPossibleBadWheels`         | 4438           |
| Lemma B.2 | Number of cartwheels whose center degree $8$ enumerated by `enumPossibleBadWheels`         | 4939           |
| Lemma B.2 | Number of cartwheels whose center degree $9$ enumerated by `enumPossibleBadWheels`         | 2409           |
| Lemma B.2 | Number of cartwheels whose center degree $10$ enumerated by `enumPossibleBadWheels`        | 567            |
| Lemma B.2 | Number of cartwheels whose center degree $11$ enumerated by `enumPossibleBadWheels`        | 38             |
| Lemma B.3 | Number of multi-boundary islands in $\mathcal{I}$ where the size of $F_R(I)$ is 0          | 254            |
| Lemma B.3 | Number of multi-boundary islands in $\mathcal{I}$ where the size of $F_R(I)$ is 1          | 88393          |
| Lemma B.3 | Number of multi-boundary islands in $\mathcal{I}$ where the size of $F_R(I)$ is 2          | 20836          |
| Lemma B.3 | Number of multi-boundary islands in $\mathcal{I}$ where the size of $F_R(I)$ is 3          | 18             |
| Lemma B.3 | Number of multi-boundary islands in $\mathcal{I}$ where the size of $F_R(I)$ is at least 4 | 0              |

Although this validation does not guarantee 100% correctness, the consistency of these key values suggests that there are no major discrepancies from our original implementation. This holds regardless of whether the source code is generated by a human or by an LLM.

## Instructions to write source code with/without LLM
This repository contains a Markdown file, `instructions.md`, intended to assist those who wish to implement the algorithms described in our paper. The file is intended for people interested in implementing the algorithms, either by hand or with the assistance of LLMs.
When using LLMs, we recommend instructing the LLM not to access the repository containing the original source code.

We used two LLMs (ChatGPT, Claude Code) to generate source code related to this paper.
For the source code generated by these LLMs, we confirmed that the key values reported above matched the expected values.
The source code is available in the following repositories:

+ [ChatGPT-generated-code](https://github.com/three-edge-coloring-apex-cubic-graphs/ChatGPT-generated-code)
+ [Claude-Code-generated-code](https://github.com/three-edge-coloring-apex-cubic-graphs/Claude-Code-generated-code)
